# FastAPI & SQLAlchemy 2.0 Engineering Standard — CampusUNSA

## 1. Overview and Mission

The `fastapi-sqlalchemy-expert` skill provides authoritative architectural guidelines for building type-safe, high-performance API endpoints and relational database models using FastAPI, SQLAlchemy 2.0, PostgreSQL 16, and Alembic.

## 2. Inviolable Constraints

1. **Zero Emojis:** Strictly prohibited in models, schemas, docstrings, and log messages.
2. **English Only:** All code entities, variables, endpoints, and comments must be in standard English.
3. **Strict Type Safety:** All functions must have complete typing annotations. Never use untyped signatures.
4. **Pydantic v2 Standard:** Use Pydantic v2 syntax (`ConfigDict(from_attributes=True)`). Never use deprecated Pydantic v1 `class Config`.
5. **Alembic Table Isolation:** Alembic migrations must strictly use `include_object` to prevent touching third-party tables (such as Evolution API Prisma tables).

## 3. SQLAlchemy 2.0 Declarative Models

All database models must use modern SQLAlchemy 2.0 mapped annotations:

```python
import uuid
from datetime import datetime
from typing import Optional
from sqlalchemy import String, DateTime, ForeignKey, func
from sqlalchemy.orm import Mapped, mapped_column, relationship
from app.core.database import Base


class ExampleEntity(Base):
    __tablename__ = "example_entities"

    id: Mapped[uuid.UUID] = mapped_column(
        primary_key=True,
        default=uuid.uuid4,
        index=True,
    )
    name: Mapped[str] = mapped_column(
        String(255),
        nullable=False,
    )
    description: Mapped[Optional[str]] = mapped_column(
        String(500),
        nullable=True,
    )
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        server_default=func.now(),
        nullable=False,
    )
```

## 4. Alembic Migration Protocol & Table Isolation

Because CampusUNSA shares a PostgreSQL instance with Evolution API, Alembic must never attempt to drop or alter external tables.

### 4.1 env.py Configuration Pattern
In `backend/alembic/env.py`, `include_object` must be configured:
```python
target_metadata = Base.metadata

def include_object(object, name, type_, reflected, compare_to):
    """Filter out tables not defined in our SQLAlchemy metadata to avoid touching external tables."""
    if type_ == "table" and reflected and name not in target_metadata.tables:
        return False
    return True

context.configure(
    connection=connection,
    target_metadata=target_metadata,
    include_object=include_object,
)
```

### 4.2 Migration Generation Workflow
```bash
# 1. Generate autogenerated migration
docker compose exec backend alembic revision --autogenerate -m "descriptive_migration_name"

# 2. Inspect generated file in backend/alembic/versions/ to verify NO drop_table for external tables

# 3. Apply migration to PostgreSQL
docker compose exec backend alembic upgrade head
```

## 5. Pydantic v2 Schemas

Always use `model_config = ConfigDict(...)` for serialization:

```python
import uuid
from typing import Optional
from pydantic import BaseModel, ConfigDict


class ExampleResponse(BaseModel):
    id: uuid.UUID
    name: str
    description: Optional[str] = None

    model_config = ConfigDict(from_attributes=True)
```

## 6. Dependency Injection Pattern

Always use `get_db` generator from `app.core.database` with FastAPI `Depends`:

```python
from fastapi import APIRouter, Depends
from sqlalchemy.orm import Session
from app.core.database import get_db

router = APIRouter()

@router.get("/items")
def list_items(db: Session = Depends(get_db)):
    return db.query(Item).all()
```
